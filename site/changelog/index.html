Six competitor sites (TeamViewer, Splashtop, 1Password, Proton, Bitwarden, Mullvad) were fetched and read directly; all six are light-dominant.     • Added Trust strip on the homepage: four specific, verifiable facts — “No account needed · No install · No data collected beyond the session · Disconnect any time” — replacing generic “safe and secure” language.
  • v0.4.0‑15
    28 August 2026
    • Added Windows Installer package (.msi). Available at flashdesk.org/dl/FlashDesk-setup.msi for users or IT administrators who prefer a traditional installation. The standalone .exe remains the primary download.
    • Fixed Session number displayed incorrectly on high-DPI screens — the last digit was clipped at 150% and 175% display scaling settings.
    • Fixed Window could not be resized smaller than its default dimensions on certain Windows visual themes that reported non-standard minimum-size constraints.
  • v0.4.0‑14
    21 August 2026
    • Fixed BlackScreen fix 9 of 9: brief black flash when the helper switched their view to the client’s secondary monitor while both monitors ran at different refresh rates. The DXGI output was being re-acquired against the wrong display sink.
    • Fixed BlackScreen fix 8 of 9: screen went entirely black on systems using AMD graphics with Windows HDR enabled. AMD’s DXGI implementation handles HDR output surfaces differently from Nvidia and Intel; the capture path now checks for HDR mode and selects the correct surface format.
  • v0.4.0‑13
    14 August 2026
    • Fixed BlackScreen fix 7 of 9: blank frames were sent when the client changed display scaling mid-session. The capture pipeline now listens for the WM_DISPLAYCHANGE message and re-initialises the output surface on any mode change.
    • Fixed BlackScreen fix 6 of 9: capture failed silently when the client toggled Windows dark mode while a session was active. Dark mode triggers a composition restart; the capture surface handle became invalid without the application being notified.
  • v0.4.0‑12
    7 August 2026
    • Fixed BlackScreen fix 5 of 9: all-black output when running under a standard (non-administrator) user account on certain Windows 11 builds. DXGI Desktop Duplication requires the calling process to be in the same session as the desktop it is duplicating; elevated calls from a different session produce a black surface rather than an error.
    • Fixed BlackScreen fix 4 of 9: capture thread stopped sending frames when the screensaver activated. Added screensaver-state detection via SystemParametersInfo(SPI_GETSCREENSAVERRUNNING); the helper now sees a grey placeholder frame rather than the session freezing on the last real image.
  • v0.4.0‑11
    31 July 2026
    • Fixed BlackScreen fix 3 of 9: capture broke on machines with two monitors at different refresh rates. The DXGI output object was being created against the wrong adapter in some multi-GPU laptop configurations where the display and render adapter are different physical devices.
    • Fixed BlackScreen fix 2 of 9: helper’s view went black on Windows 11 24H2 after the client machine woke from sleep. The DXGI capture surface must be re-acquired after a display power-state transition; the previous code held a stale handle.
  • v0.4.0‑10
    24 July 2026
    • Changed Screen capture switched from GDI BitBlt to DXGI Desktop Duplication API. DXGI is the correct capture path for modern Windows display drivers and works regardless of the display’s hardware composition mode. GDI remains as a fallback for the minority of systems where DXGI Desktop Duplication is unavailable (pre-Windows 8 or very old driver stacks).
    • Fixed BlackScreen fix 1 of 9: helper’s view went entirely black on some Windows 11 systems. The root cause was GDI capture failing silently on displays that use a hardware composition path GDI cannot read. The DXGI switch in this release is the foundational fix; subsequent releases address edge cases the new path exposed.
  • v0.4.0‑9
    15 July 2026
    • Added Relay architecture. Traffic now routes through a relay server rather than requiring a direct peer-to-peer path. This resolves connection failures behind symmetric NAT and strict corporate or ISP-level firewalls, which previously made the tool completely unusable for a significant proportion of users who reported “stuck at connecting.”
    • Changed Connection setup time reduced significantly. The relay handles NAT traversal; the two-party handshake that previously took up to 12 seconds in the best case now typically completes in under 3 seconds.
    • Fixed Connections failed completely when the client was behind a firewall that blocks all UDP. The relay communicates over TCP 443, which is open on virtually every network that allows web browsing at all.
  • v0.4.0‑8
    26 June 2026
    • Fixed Accept/Reject consent dialog occasionally appeared behind other open windows, making it look as though FlashDesk had stopped responding. The dialog is now forced to the foreground (SetForegroundWindow) and taskbar-flashed when it opens so the user knows action is needed.
    • Fixed In rare edge cases involving a suspended process or paused debugger, a session could silently resume after the 90-second reconnect window had expired. The resume timer now runs in a separate thread that is not affected by process suspension.
  • v0.4.0‑7
    12 June 2026
    • Added File transfer panel. The helper can send individual files to the client machine during an active session; files arrive in the client’s Downloads folder with a desktop notification. Transfer is intentionally one-directional: the helper can push files to the client, but the client cannot send files to the helper. There is no mechanism for the helper to browse or pull files.
    • Fixed Amber live-session band was not consistently visible when the helper had the FlashDesk window maximised on a secondary display. The band is now rendered in a separate always-on-top layer so it cannot be obscured by the helper’s own maximised window.
  • v0.4.0‑6
    29 May 2026
    • Fixed Application crashed on startup on machines with no active network adapter. FlashDesk does not require a network connection to start — the session number can be generated and the UI shown without one. The crash was an incorrect assertion during the adapter enumeration step.
    • Fixed The 9-digit session ID occasionally displayed as an 8-digit number when the first generated digit was zero. The display now always zero-pads to exactly 9 digits.
  • v0.4.0‑5
    8 May 2026
    • Added Multiple-monitor support. When the client has more than one display connected, the helper sees a monitor selector and can switch between them during the session. Only one display is shared at a time; the helper cannot view all monitors simultaneously.
    • Fixed Stop-sharing button required a double-click to register on machines with pointer acceleration set above the Windows default value. The hit-test area was smaller than the rendered button bounds due to a rounding error in the layout calculation.
  • v0.4.0‑4
    24 April 2026
    • Changed Replaced the fixed listening port (7890) with dynamic port selection. FlashDesk now picks an available port at startup rather than requiring port 7890 to be free. This resolved conflicts with other software that happened to bind the same port.
    • Fixed Active session was dropped when the client machine entered a brief sleep state (e.g. lid-close on a laptop). The connection now waits up to 90 seconds for the client to resume before ending the session — the same window that applies to a dropped network connection.
  • v0.4.0‑3
    10 April 2026
    • Added Session log. Each completed session appends one line to %APPDATA%\FlashDesk\sessions.log: date, start time, and duration only. No screen content, keystrokes, clipboard data, or file names are recorded. The log file is stored only on the client’s machine and is never transmitted anywhere.
    • Fixed The Reject button in the Accept/Reject consent dialog was not reachable by keyboard navigation. Tab order now places focus on Reject first — the safer default — and then on Accept.
  • v0.4.0‑2
    27 March 2026
    • Fixed Closing FlashDesk left a Windows Firewall inbound exception entry behind. The rule is now removed on clean exit and on any unexpected shutdown FlashDesk can detect.
    • Fixed Window position was not remembered between runs. FlashDesk now saves and restores its last screen position on startup.
    • Fixed The Copy button occasionally copied the session number from the previous run rather than the current one when restarting FlashDesk quickly.
  • v0.4.0‑1
    14 March 2026
    • Added First public release. Core remote view and control: the helper sees the client’s screen and can move the mouse and type; the client watches everything and can end the session at any moment.
    • Added 9-digit session ID scheme. A new number is generated on each run; it is never reused between sessions.
    • Added Accept / Reject consent dialog. The first connection from any helper always requires the client to press Accept before anything gets in. There is no way to bypass this; it is enforced in the server code, not the UI layer.
    • Added Amber live-session band. A coloured band appears across the top of the FlashDesk window the moment a helper connects and disappears the moment they disconnect. It cannot be dismissed, minimised, or hidden by the helper.
    • Added Stop-sharing button. One click ends the session immediately, regardless of what the helper is currently doing on screen.

Version numbering: versions are numbered v0.4.0-N where N is an incrementing build number. Build 1 was the first public release; each higher number is a separate release shipped after it. The v0.4.0 prefix will advance when the feature set changes substantially — a change in the first three numbers will always be noted here with an explanation.

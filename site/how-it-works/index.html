How it works

Every sentence on this page describes something the program actually does, not something it is meant to do. If a claim could not be checked against the code, it is not here.

The file panel can copy a file. It cannot delete, rename or move anything.

What a session can do

Nothing installs

It is one file. There is no installer step, and no administrator password is asked for to run it — the program starts with the same permissions as any other window you open. (A separate, optional "install it properly" mode has been talked about but does not exist yet — today, everyone runs the same portable file.)

The number is an address, not a password

Your 9-digit FlashDesk number is generated on your machine and identifies it to the relay that connects two computers together — it is how a helper finds you, the way a phone number finds a house. It proves nothing about who is allowed in on its own; a separate, private value your computer never displays is what actually proves ownership of that number to the relay, and the relay checks it on every connection.

Every session is accepted by hand

An incoming connection shows a dialog with the caller's number and two buttons, Accept and Reject. While that dialog is open, FlashDesk's own remote-control input is blocked from reaching it — the program that is asking for control cannot also be the thing that presses Accept.

A strip stays on screen, and cannot be hidden

While anyone is connected, a coloured band stays on your screen for the whole session. It belongs entirely to the window running on your own computer — there is nothing the connected helper can send that touches it. It disappears when the session ends, not before.

A log stays on your computer

Every connection — who asked, when, whether you accepted or refused — is written to a plain text file on your own machine. It never leaves it. It does not record your screen, anything you typed, or the contents of any file — only that a connection happened and what was decided about it.

File access is a second, separate question

Being watched and being read through are not the same thing. Accepting a session lets a helper see your screen; it does not by itself let them open your files. Looking at your files needs its own, separate permission, asked for the first time it is needed.

Copy, never delete or rename

Once file access is granted, a helper can look through your files and copy one to their own computer, or send you one of theirs. There is no delete, rename or move — those simply do not exist as things the file panel can ask your computer to do, by design: anything a helper needs to delete or rename, they can already do the ordinary way, in front of you, with the mouse.

An arriving program is named every time

If a helper sends you a program rather than an ordinary file, you are asked about it by name — the file's name and where it would be saved — every single time, even after you have already agreed to file access generally. Agreeing once to look at files is not the same as agreeing to run something.

What it does not do

  • No background service. FlashDesk only runs while its window is open.
  • No autostart. It does not add itself to Windows' startup list or run when you log in.
  • Closing the window ends everything — the session, the capture, the connection. There is nothing left running afterward.
  • If your computer has more than one screen, your helper can switch between the ones they can reach. This has not yet been verified on real multi-monitor hardware — if anything looks wrong when they switch, tell them, and they can stay on one screen for the rest of the session.
